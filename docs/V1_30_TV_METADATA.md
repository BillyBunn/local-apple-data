# v1.30 Apple TV Metadata

## Goal

Add a read-only Apple TV surface for locally synced TV.app item, playlist, and exact selected-playlist item metadata without returning video bytes, local file paths, artwork, descriptions, playback state, watched state, ratings, raw identifiers, broad playlist item dumps, or mutating TV.app.

Apple documents iCloud-backed TV library behavior through the Apple TV app and local library management. On this Mac, the default local TV library package exists at `~/Movies/TV/TV Library.tvlibrary`, but `Library.tvdb` is a proprietary binary store rather than SQLite. The first publishable tranche therefore avoids raw binary parsing and uses bounded read-only TV.app automation.

## Implemented Surface

- `local-apple-data tv search --json --query <text>`
- `local-apple-data tv get --json --handle <tv:item:v1:...>`
- `local-apple-data tv playlists --json --query <text>`
- `local-apple-data tv playlist --json --handle <tv:playlist:v1:...>`
- `local-apple-data tv playlist-items --json --handle <tv:playlist:v1:...>`
- MCP `tv_search`
- MCP `tv_get_item`
- MCP `tv_search_playlists`
- MCP `tv_get_playlist`
- MCP `tv_list_playlist_items`

Searches require a specific title, show, artist, genre, kind, or playlist term. Empty, wildcard-like, and broad library queries are rejected before automation runs.

## Returned Metadata

- Opaque `tv:item:v1:` or `tv:playlist:v1:` handles.
- Item title, show, artist, genre, video kind, duration, season number, episode number, and year when TV.app exposes them.
- Playlist title, kind, count, and duration when TV.app exposes them.
- Capped selected-playlist item title, show, artist, genre, video kind, duration, season number, episode number, and year when TV.app exposes them.
- Store fingerprint and safe warning codes.

## Explicitly Not Returned

- Video bytes, local file paths, artwork, descriptions, transcripts, captions, or downloaded media.
- Raw TV persistent IDs, raw database IDs, or direct `Library.tvdb` rows.
- Playback state, watched state, play counts, ratings, favorites, or broad playlist item dumps.
- Broad library dumps, raw TV library parsing, iCloud media fetch, private Apple APIs, TV.app playback/queue control, or TV.app mutation.

## Implementation Notes

- The first tranche uses bounded TV.app AppleScript automation through `osascript` because the local `Library.tvdb` format is proprietary and not SQLite.
- Health checks only for `osascript`, TV.app-style automation readiness, and the default TV library package; health does not open TV.app or inspect TV items.
- Runtime verification uses a synthetic runner. It does not read the operator's real TV library.
- Search and detail calls clamp `max_scan_items` to 5000 and result limits to 50.
- Detail and selected-playlist item calls require exact opaque handles generated by search output and reject raw identifiers, fabricated handles, and old handle shapes.

## Verification

- Adapter tests cover search, exact get, playlist search/get, selected playlist-items, broad query rejection, scan clamping, automation errors, missing-persistent-ID skipping, and redaction guarantees.
- CLI tests cover all five TV commands.
- MCP tests cover tool registration and invalid-handle rejection.
- Health and surface-contract tests cover TV readiness and CLI/MCP/docs alignment.
- Runtime smoke covers opaque TV handles and redaction guarantees through a mocked runner.
